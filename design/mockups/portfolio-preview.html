01

Multimodal search

2026

TraceVision

Search videos. Find the moment behind an answer.

A local video-search prototype that combines object tracks, speech transcripts and visual retrieval to return answers with timestamped evidence.

My part. I built the indexing pipeline, reusable stage caches, bilingual query planner and FastAPI / React workspace.

GitHub repository ↗
Design decisions & evaluation

A decision I made

Reuse persisted evidence before running models again. A rule-based planner keeps supported English and Vietnamese queries predictable, but handles fewer paraphrases.

What I measured

The planner matched 35 of 40 authored evaluation queries. Warm-cache indexing was 52.3× faster across 15 short videos on an RTX 4050 Laptop GPU.

Limits of the result

This is a short-video local benchmark. Query-plan match measures parsing, not answer accuracy; cache reuse is not end-to-end inference speed.

02

Document retrieval

2026

Subject Knowledge Hub

Ask your PDFs. Keep the source page attached.

A Vietnamese and English PDF application with subject-scoped retrieval, version-specific page citations and document ingestion that can resume after interruption.

My part. I built the application, versioned document pipeline, retrieval filters and Celery workers with PostgreSQL checkpoints.

GitHub repository ↗
Design decisions & evaluation

A decision I made

Activate document versions atomically and retain historical citations. This improves recoverability, at the cost of more database state and worker coordination.

What I measured

Page-boundary chunking used 25.3% fewer provider input tokens on 70 held-out synthetic bilingual questions. Three interrupted jobs recovered in controlled process-kill tests.

Limits of the result

The token comparison uses synthetic material. Recovery was tested with fixture embeddings. These results do not establish production reliability or answer accuracy.

03

Computer vision · RIVF 2026, accepted

04/2026 – 06/2026

AQB-FAS

Face anti-spoofing with a smaller payload.

A split-computing framework that sends a fixed-size facial representation from an edge encoder to a server-side classifier.

My part. As first author, I proposed the core idea and architecture, led evaluation and interpreted the threshold-policy and deployment results.

GitHub repository ↗
Design decisions & evaluation

A decision I made

Transmit a fixed 64-byte latent instead of an image. This reduces communication, but introduces a representation bottleneck and cross-domain robustness trade-offs.

What I measured

A 64-byte payload replaces a 150,528-byte RGB input. CelebA-Spoof test accuracy was 97.01%, with 2.66% ACER at a validation-selected threshold.

Limits of the result

Edge-encoder timing was measured on Intel Arc B580. It excludes network latency; source-domain performance does not guarantee cross-domain robustness.
